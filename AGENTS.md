# Repository Guidelines

## Project Structure & Module Organization
- `src/` holds the TypeScript source. `src/index.ts` is the plugin entry point, `src/keys.ts` builds the quorum key structures, and `src/types.ts` defines shared types and ledger limits.
- `src/tools/` implements the agent tools, one file per tool.
- `tests/` contains Vitest suites: `tests/keys.test.ts` covers key construction, `tests/tools.test.ts` covers tool surface and schemas.
- `scripts/integration-test.mjs` exercises the plugin against a live network.
- `docs/` holds `TOOLS.md`, `CONFIGURATION.md` and `EXAMPLES.md`.
- `dist/` is generated by `tsup` from `src/index.ts`; do not edit by hand.
- Root configs live in `tsconfig.json`, `tsup.config.ts`, `biome.json`, and `package.json`.

## Build, Test, and Development Commands
- `npm run dev` runs `tsup --watch` for local iteration.
- `npm run build` emits `dist/` bundles and types.
- `npm run typecheck` runs `tsc --noEmit` against `src/` and `tests/`.
- `npm run lint` runs Biome checks; `npm run format` applies formatting.
- `npm run test` runs Vitest once; `npm run test:watch` keeps it in watch mode.
- `npm run test:integration` creates a real settlement account and obligation; set `HEDERA_NETWORK`, `HEDERA_ACCOUNT_ID` and `HEDERA_PRIVATE_KEY` first.

## Coding Style & Naming Conventions
- Biome enforces two-space indentation, double quotes and a 100-character line width. Run `npm run format` before committing.
- Tools are classes named `<Thing>Tool` extending `BaseTool`, exported as a lower-camel instance (`export const commitSettlementTool = new CommitSettlementTool()`), and registered in `src/index.ts`.
- Tool `method` names are snake_case and prefixed `settlement_`.
- Zod schemas carry `.describe()` on every field: those strings are what the model reads.

## Testing Guidelines
- Unit tests must not touch the network. Build transactions and assert on their shape instead.
- Anything that asserts a safety property — that attesters alone cannot spend, that the 62-day cap holds — belongs in `tests/`, not in prose.

## Security Notes
- Private keys must never appear in a tool parameter; they would land in the model's context. Signing belongs to whoever owns the key, via the agent's own operator or `AgentMode.RETURN_BYTES`.
- Only public keys cross the tool boundary.
